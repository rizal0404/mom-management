## Temuan, menurut prioritas

### A01 — P1: finalisasi mengabaikan perubahan yang belum disimpan

- Lokasi: `src/modules/meetings/MeetingEditorPage.tsx:104–110,133`.
- Reproduksi: buka draf tersimpan → ubah Hasil → langsung Finalisasi → konfirmasi. Layar menampilkan hasil baru sebagai notula final; reload menampilkan hasil lama.
- Penyebab: RPC hanya menerima ID/versi dan memfinalkan data tersimpan. UI tidak memeriksa `isDirty`, lalu menampilkan state form lokal sebagai data final.
- Dampak: keputusan, PIC, jadwal, dan jumlah action yang dikonfirmasi dapat berbeda dari data yang benar-benar dikunci; operator berpotensi kehilangan kesepakatan rapat.
- Bukti: `dirty_finalization.displayedUnsavedAsFinal=true`; [sebelum reload](audit-2026-09-22/final-before-reload.png) dan [sesudah reload](audit-2026-09-22/final-after-reload.png).
- Perbaikan: blokir finalisasi saat draf kotor atau simpan dahulu dan gunakan versi hasil simpan; setelah finalisasi baca ulang detail server. Uji perubahan hasil/PIC/jadwal dan penambahan item sebelum finalisasi.

### A02 — P1: action di luar 25 record pertama tidak dapat dibuka

- Lokasi: `src/modules/actions/actionService.ts:135–139`.
- `getAction(id)` mengambil `getActionRows()` dengan default halaman 1/25, baru mencari ID di array tersebut. Ini berlaku juga ketika action terlihat melalui filter atau timeline.
- Reproduksi: buat 30 action, buka ID yang ada di database tetapi berada setelah urutan 25 pertama. UI menampilkan “Tindak lanjut tidak ditemukan atau tidak dapat diakses”.
- Bukti: `action_after_first_25`; [screenshot](audit-2026-09-22/detail-after-25.png).
- Perbaikan: query langsung `.eq('id', id).maybeSingle()` dengan RLS, lalu hydrate record itu. Uji detail dari halaman kedua, hasil pencarian, timeline, dan direct URL.

### A03 — P1: menghapus agenda awal membuat simpan draf gagal

- Lokasi: `supabase/migrations/20260921130500_mom_005_draft_metadata_and_assignments.sql:55–79`; constraint di migration schema `meeting_items_position_once`.
- Reproduksi: draf berisi item posisi 1 dan 2; hapus item pertama dan simpan item kedua sebagai posisi 1.
- RPC memperbarui posisi item kedua sebelum menghapus item pertama, sehingga unique `(meeting_id, position)` bertabrakan.
- Bukti RPC: SQLSTATE `23505`, `duplicate key value violates unique constraint "meeting_items_position_once"`.
- Perbaikan: migration baru dengan strategi penghapusan/reindex atomik yang aman terhadap unique constraint dan tetap mempertahankan ID item. Uji hapus awal/tengah dan perubahan urutan; transaksi gagal harus tetap tidak merusak draf lama.

### A04 — P2: `expected_version=null` melewati proteksi konflik

- Lokasi: `supabase/migrations/20260922100000_mom_006_action_tracker.sql:51`; pola serupa pada finalisasi baris 9 dan delete draf migration awal.
- Perbandingan `version <> null` tidak bernilai true, sehingga exception CONFLICT tidak dijalankan.
- Bukti: `update_action` dengan versi null berhasil menaikkan versi; `null_expected_version.accepted=true`. Jalur finalisasi/delete terindikasi oleh source, belum diuji terpisah dengan null pada audit.
- Dampak: caller terotorisasi dapat menulis tanpa versi yang dibaca dan melewati aturan anti-overwrite. Ini bukan bukti akses pengguna tidak berhak.
- Perbaikan: tolak null secara eksplisit atau gunakan perbandingan null-safe; tambah uji null/stale/current untuk setiap RPC write.

### A05 — P2: deadline/PIC dapat diubah tanpa alasan

- Lokasi: `supabase/migrations/20260922100000_mom_006_action_tracker.sql:85–92`.
- Catatan wajib hanya untuk transisi status tertentu; perubahan field owner/admin tidak mewajibkan alasan seperti kontrak produk.
- Bukti: update deadline oleh owner dengan `p_note=null` diterima (`deadline_without_reason.accepted=true`). Audit tetap tersimpan, tetapi tanpa alasan.
- Perbaikan: bandingkan nilai sebelum/sesudah field kesepakatan dan wajibkan alasan jika berubah. Uji juga perubahan PIC dan jadwal tanpa mengubah status.

### A06 — P2: navigasi dalam aplikasi menghilangkan draf kotor tanpa peringatan

- Lokasi: `src/modules/meetings/MeetingEditorPage.tsx:56–62`.
- `beforeunload` hanya melindungi perpindahan dokumen browser, bukan navigasi React Router.
- Bukti: isi judul baru → klik Dashboard di sidebar → berpindah tanpa dialog (`dirty_internal_navigation.leftWithoutWarning=true`).
- Perbaikan: navigation blocker router, termasuk back dan logout; pertahankan beforeunload. Uji Batal/Tinggalkan dan jangan menghalangi navigasi setelah simpan berhasil.

### A07 — P2: timeline tetap error setelah jaringan pulih

- Lokasi: `src/modules/actions/TimelineView.tsx:47–60`.
- Query baru pada perubahan pekan/filter tidak membersihkan error lama; hanya changePage yang membersihkannya. Pada error awal, kontrol pagination tidak tersedia.
- Bukti: gagalkan request timeline → pulihkan jaringan → ganti pekan → request 200 tetapi “Timeline tidak dapat dimuat” tetap terlihat.
- Perbaikan: lifecycle loading/error per query dan tombol retry timeline sendiri. Uji error lalu retry, ganti pekan, dan filter; jangan tampilkan data pekan lama dengan header pekan baru saat loading.

### A08 — P2: dashboard menghitung hanya hasil yang dibatasi API

- Lokasi: `src/modules/dashboard/dashboardService.ts:53–57`; `supabase/config.toml:18` menetapkan `max_rows=1000`.
- Query semua status tidak memakai pagination atau agregasi database. Di atas 1.000 actions, perhitungan tidak mencakup seluruh record yang dapat diakses, berlawanan dengan PRODUCT_SPEC.
- Bukti: analisis query dan batas konfigurasi, bukan pengujian 1.001 record. Unit test hanya menguji array kecil yang diberikan langsung, sehingga tidak memeriksa batas pengambilan data.
- Perbaikan: agregasi/count berotorisasi di server atau fetch seluruh halaman; uji batas 1.000/1.001 dan semua CANCELLED. Jangan menaikkan limit saja sebagai solusi permanen.

- Visual saat ini hijau-lime/M3, berbeda dari token abu-abu/putih/biru pada UI_GUIDELINE awal. Ada `fino-dashboard-ui-spec.md` dan catatan implementasi M3.
